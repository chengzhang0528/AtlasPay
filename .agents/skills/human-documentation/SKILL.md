# 人类文档

为开发者写能够从唯一入口选择场景、照做并判断结果的中文文档。先确定读者、任务与事实所有者，再决定位置和结构；不要把正式契约、智能体治理或脚本索引复制成人类手册。

## 放置

| 内容 | 位置 |
|---|---|
| 跨项目上手、开发流程和面向人的任务导航 | `/人类-文档/` |
| 与单个源码目录绑定的构建、调试或维护说明 | 对应源码根或功能目录的 `README.md` |
| 产品规则、能力边界和长期技术设计 | `文档/` 下职责唯一的正式事实所有者 |
| 智能体路由、治理动作和可重复操作契约 | `AGENTS.md`、Workflow、Runbook 或 `.agents/skills/` |

请求混合多类内容时，先更新真实事实所有者，再让人类文档用链接和任务步骤消费它。不要让人类文档成为公共契约或源码行为的第二事实源。

## 执行顺序

1. 识别读者和任务，明确环境、前置条件、动作和可观察结果。
2. 查证真实脚本、源码、配置、测试、`package.json` 和邻近 README；核实默认路径、输出、停止、失败和副作用。
3. 只有现有入口能从前置条件走到承诺结果时才创建任务页；缺实现就记录缺口，不编造流程。
4. 根 README 只做最短任务导航，`/人类-文档/README.md` 做完整导航，任务页负责执行；避免把人类 README 加入智能体默认必读。
5. 按首次完成、日常重复、修改后验证等人的场景组织，而不是按脚本全集组织。
6. 从入口逐步模拟读者；每一步都必须知道执行位置、成功标志、失败入口、重跑方式和停止方式。
7. 对部署、发布、安装、卸载、生成文件、版本修改和远端写操作明确目标、影响和停止条件。
8. 验证命令、路径、语义链接和可观察结果，删除治理话术、重复背景、占位符和无证据捷径。

## 写作规则

- 默认中文；命令、代码标识、配置键、文件名和既有专有名词保持原文。
- 标题回答读者现在要做什么；一个步骤只表达一个动作，并紧跟必要参数、预期结果和失败下一步。
- 人类任务页文件名去掉 `.md` 后与 H1 完全一致；`README.md` 只作为目录入口。
- 不添加正式治理元数据，不复制可从源码、测试或正式契约低成本获得的细节，不使用未验证的自动打开、热重载或发布成功声明。
- 命令中禁止 `<version>`、`<host>`、`{name}`、`$VERSION` 等占位符；缺值时先查证或询问。
- 不把密码、Token、私钥或连接串写进文档；只写已确认的本机凭据位置或配置键。
- 单份操作指南默认不超过 60 行；超出时按独立任务拆分。

## 验证

- 从入口逐个打开新增或变更的相对链接。
- 将 `npm run <script>` 与根 `package.json` 对照，将其他命令与实现对照。
- 静态 dry run 最短成功路径，核对执行目录、前置条件、真实输出、访问入口、日志、停止/重跑方式和副作用。
- 确认没有复制正式事实、创建空目录或把人类文档加入智能体默认热路径。
- 运行 `npm run check:docs`；若修改了校验器或代码，再运行命中范围的测试。
