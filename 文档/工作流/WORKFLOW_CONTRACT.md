本文只定义何时选择哪一个工作流，以及 Action 的稳定输入、输出与停止条件。具体搜索、编辑、编码和验证方法由当前任务、源码、测试与命中的专业方法决定。

## 选择规则

| 触发 | 主工作流 | 转换 |
|---|---|---|
| 修改正式文档、任务控制或治理配置，但不改变技术执行逻辑 | [WF-0001 日常变更](WF-0001-日常变更.md) | 完成、取消或受阻前进入 WF-0004 |
| 修改源码、数据、API、构建、治理校验代码或技术执行逻辑 | [WF-0002 技术变更](WF-0002-技术变更.md) | 持续阻断进入 WF-0003；结束前进入 WF-0004 |
| 用户要求调查、诊断、评审，或现有工作出现跨会话阻断 | [WF-0003 调查与阻断](WF-0003-调查与阻断.md) | 获得实现授权后转 WF-0001 或 WF-0002 |
| 任一会改变工作空间的任务准备报告完成、取消或未完成 | [WF-0004 任务收口](WF-0004-任务收口.md) | 输出唯一结果 |

只选择一个主工作流；WF-0004 是所有变更任务的共同收口。权限、范围或任务类型不明时停止确认，不拼接新流程。

## 执行强度

- **即时变更**必须同时满足：当前回合可完成；授权与验收清楚；影响文件与消费者可枚举；无跨会话恢复、部分发布或回滚状态；不改变公共 API/DTO、数据库或迁移、权限/安全/租户边界、跨项目契约、部署方式、业务能力边界、不变量、持久化状态或对外兼容策略。
- **受控变更**是任一即时条件不成立，或用户明确要求方案、迁移、跨模块或跨项目实施。它必须有可恢复任务入口；受控技术变更还必须有 Active ChangePlan。
- **治理控制面强制受控**：改变根、项目或源码入口 AGENTS、WorkflowContract、Workflow、StructureContract、治理校验器，以及任务、方案、安全、验证或收口门禁时始终受控。
- 实施中发现风险升级时，立即转为受控变更并补齐任务与方案，不得拆小范围规避门禁。

## Action 契约

| Action | Trigger | Input | Output | Key Constraints / Stop When |
|---|---|---|---|---|
| `ACT-CLASSIFY-REQUEST` | 接收或恢复请求 | 用户目标、当前任务与状态 | 主工作流或无需工作流 | 权限、范围或类型不明时停止 |
| `ACT-REGISTER-TASK` | 受控变更、跨会话、持续阻断或活动文档 | 目标、范围、验收、入口 | `TASK_CONTROL.md` 唯一当前项 | 即时变更不登记 |
| `ACT-ROUTE-CONTEXT` | 主工作流已确定 | 当前任务与项目入口 | 最少必要事实源和方法 | 不遍历无关文档，不用归档推断当前事实 |
| `ACT-OPEN-PLAN` | 受控技术变更准备编码 | 基线、边界、成功与停止条件 | WF-0002 Active ChangePlan | 找不到真实长期所有者时停止 |
| `ACT-VERIFY-BASELINE` | 判断或实施前 | 源码、类型、测试、正式来源 | 当前态、差异和未知项 | 来源冲突或关键事实缺失时停止扩张 |
| `ACT-EXECUTE-CHANGE` | 前置条件满足 | 授权任务与方案 | 最小工作空间增量 | 不扩张产品、服务、安全或依赖边界 |
| `ACT-CAPTURE-BLOCKER` | 问题跨会话且影响任务 | 证据、影响、边界、下一入口 | 任务状态与唯一 Issue | 临时错误和日志不沉淀 |
| `ACT-VERIFY-RESULT` | 增量已形成 | 验收、范围验证入口 | 通过、失败或阻断证据 | 验证失败不得报告完成 |
| `ACT-CLASSIFY-KNOWLEDGE` | 收口前 | 已验证长期事实增量 | 更新目标或无增量判定 | 不为留痕创建占位文档 |
| `ACT-RECONCILE-KNOWLEDGE` | 存在长期事实增量 | 分类与唯一所有者 | 当前事实与实现一致 | 所有者不明或冲突时停止 |
| `ACT-RESOLVE-ACTIVITY` | 完成、取消或继续受阻 | 任务、活动文档、验证 | 正确活动状态 | 未完成不得删除恢复入口 |
| `ACT-ARCHIVE-RESULT` | 已登记结果影响后续选择 | 任务、结果、长期入口、最小验证 | 一行完成事实 | 即时或代码可重建结果不归档 |
| `ACT-VALIDATE-DOCS` | 正式文档或入口变化 | 当前文档树与结构契约 | 治理检查结果 | 失败不得收口 |
| `ACT-REPORT-RESULT` | 当前回合结束 | 变更、状态和验证证据 | 可核验最终汇报 | 不省略未运行验证及原因 |

## 公共门禁

- Action 是条件契约，不是每个任务都要执行的固定清单；无真实输入或输出的 Action 必须跳过。
- 新增 Workflow 或 Action 前先证明现有契约无法表达稳定边界；不得为单个命令、日期、人员或一次任务新增。
- 工作流只回答“应该做什么”；任务特有顺序归 ChangePlan，实际行为归源码与测试。
